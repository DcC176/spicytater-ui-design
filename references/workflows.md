# UI 方案组合与验收

以下内容来自本次整理的方案建议，需结合真实任务选择。来源快照日期为 2026年10月4日。

## 先按页面任务选择方案

下表是整理建议，用于缩小候选范围，不表示网站作者对特定项目的推荐。

| 页面任务 | 候选风格 | 先解决的问题 |
| --- | --- | --- |
| 效率工具与后台 | 现代简约、Fluent、Material、深色界面 | 当前任务、命令和结果是否连续可见 |
| 多模块首页 | Bento Grid | 主任务为何获得更大空间，辅助模块承担什么职责 |
| 软件试用与企业采购 | SaaS 官网、B2B 官网 | 价值、工作流、可信证据与下一步决策 |
| 文章与文化内容 | 编辑风、瑞士排版、单色 | 阅读顺序、元信息和继续浏览路径 |
| 品牌与商品 | DTC、有机设计、装饰艺术 | 材料、规格、信任、价格和购买关系 |
| 社区活动与创意项目 | 手绘、孟菲斯、趣味插画、极繁主义 | 氛围如何解释活动内容而非盖住入口 |
| 媒体与游戏 | Y2K、像素、玻璃拟态、未来主义 | 内容主体、当前状态与控制方式 |
| 公共服务与高可读性页面 | 高对比、扁平化、瑞士排版 | 字段、状态、错误和操作的明确辨认 |

## 常见组件选择边界

下表是依据词条整理的判断辅助。

| 要解决的问题 | 优先考虑 | 容易混淆之处 |
| --- | --- | --- |
| 填一条短自由值 | Input | 长段说明应交给 Textarea |
| 输入可换行的描述 | Textarea | 不用单行输入框挤压长内容 |
| 从固定集合中挑选 | Select 或 Radio | 自由文本不能替代合法选项集合 |
| 多项可同时成立 | Checkbox | 互斥选项不能使用独立多选 |
| 设置持续的开启关闭状态 | Switch | 一次动作应由 Button 执行 |
| 执行保存等动作 | Button | 跳转页面用 Link |
| 同一对象内切换区域 | Tabs | 不自动等同于跨页面导航 |
| 阅读一个对象的属性 | Descriptions | 多条记录比较应考虑 Table |
| 有顺序的一组对象 | List | 视觉卡片并不必然意味着列表失去顺序 |
| 一维对齐 | Flex | 二维轨道关系应考虑 Grid |
| 多模块优先级布局 | Bento Grid | 不同大小的卡片须共享网格且解释权重 |
| 局部补充说明 | Popover | 必须说明关闭行为和返回原任务的位置 |

## 可复用方案组合

以下是本次整理编写的方案，不是网站已发布的完整产品或经过实测的模板。它们展示怎样把多个来源条目转化成具体需求。

### 产品与效率工作台

参考 STYLE-06 现代简约、STYLE-02 Bento Grid、STYLE-17 Fluent。先用标题和主任务区说明当前要做什么，再列待办、进度和近期事项。UI-26 List 承接连续任务，UI-27 Statistic 表达进度，UI-06 Button 执行处理。如果内容重要性相近，不必强行拼成大小不一的便当格。

验收建议：首屏能找到主任务；统计数字有单位和时间范围；完成操作后任务状态同步；失败时保留上下文；窄屏按任务优先级排列。

### 软件与企业介绍页

参考 STYLE-08 SaaS 官网、STYLE-11 B2B 官网。页面依次回答目标用户是谁、产品解决什么、如何使用、有哪些可验证证据、怎样继续。套餐比较可用 UI-28 Table；预约或咨询使用 UI-10 Form。未获得真实证据时，用标明“示例”的内容占位。

验收建议：主要入口说明用户会得到试用、演示或咨询中的哪一种；价格条件可读；表单错误定位到字段；不编造客户与转化指标。

### 知识库与阅读系统

参考 STYLE-27 Notion 风、STYLE-15 编辑风、STYLE-09 瑞士排版。用 UI-40 Sidebar 保留章节路径，UI-03 HTML 与 UI-04 Markdown 组织正文，UI-29 Tabs 在同一对象的不同视图中切换。持续编辑需求应另行定义保存和权限，不因视觉像知识库就默认已经具备编辑功能。

验收建议：章节入口定位正确；当前位置明确；标题、作者与日期可查；手机目录可打开关闭；长标题、表格和代码不挤出页面。

### 品牌商品与购买流程

参考 STYLE-14 DTC、STYLE-28 有机设计或 STYLE-01 装饰艺术。产品对象先于氛围装饰；材料、规格、售价、配送与售后共同支撑选择。UI-16 Select 或 UI-14 Radio 承接合法规格，UI-12 InputNumber 承接数量。购买行为及支付规则须由实际业务明确。

验收建议：价格与规格一致；不可用选项有说明；数量边界一致；组合选择能解释差异；示例页不冒充已接通真实订单与支付。

### 创意活动与作品展示

参考 STYLE-20 手绘、STYLE-23 孟菲斯、STYLE-07 趣味插画或 STYLE-22 极繁主义。作品、日程与名额是实际对象；线条、图形和插画用于引导阅读。UI-24 Card 展示单个作品，UI-34 Card Grid 对齐同类项目，报名流程用 UI-10 Form。

验收建议：活动时间、地点与报名条件可见；装饰不覆盖正文；图像缺失时仍能理解项目；窄屏降密度而不删掉关键事实。

## 通用验收建议

这些检查项由本次整理提供，并参考网站反复强调的任务、状态与窄屏阅读要求。未对所有网站交互逐一执行这些测试。

1. 信息层级：用户能辨认页面主体、当前状态与第一个主要动作；装饰与视觉权重能解释其职责。
2. 内容真实性：日期、金额、单位、指标基准与业务来源一致；演示和缺失数据有标识，不伪造客户结果。
3. 控件语义：动作与跳转区分；固定集合与自由值区分；单选与多选区分；标签持续可见。
4. 交互结果：按实际功能验证空值、选中、加载、禁用、成功和失败；不要求与当前任务无关的状态或功能。
5. 输入边界：验证真实业务的范围、步长、必填与合法集合；错误后能修正，不丢失用户已输入的信息。
6. 响应式：网站多种风格词条提及 720px、390px 与 320px；本资料建议也检查实际桌面尺寸。窄屏重排内容，关键文字与主要按钮不裁切；需要二维比较的表格单独定义可访问方案。
7. 可访问性：键盘可到达操作，焦点可见，状态不只依赖颜色；透明、深色与低对比材质不会使关键内容消失。
8. 动态效果：动画说明变化而非抢注意力；在需要时尊重减少动态效果的用户设置。
9. 保存与恢复：依据真实任务确认临时页面状态和持久业务数据；显示成功必须有相应结果支撑。
