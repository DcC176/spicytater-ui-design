## 40 个前端与交互词条

案例描述依据网站词条归纳；实现与验收要求为整理建议。分组沿用网站目录，链接虽涉及导航，也按来源归入表单分组。

### 网页基础

#### UI-01 组件 Component

来源：[对应词条](https://spicytater.cn/terms/component)。

案例概括：个人信息在资料页与评论区同步展示。

整理建议：提取真正重复的同类界面；共享样式与字段结构，实例数据分别传入。验证共同修改生效且其他内容不变。

#### UI-02 前端 Frontend

来源：[对应词条](https://spicytater.cn/terms/frontend)。

案例概括：编辑个人昵称并显示保存结果。

整理建议：界面负责采集输入、发出请求和呈现回执；区分提交中、成功与失败，不以按钮点击替代后端成功。

#### UI-03 HTML

来源：[对应词条](https://spicytater.cn/terms/html)。

案例概括：旅行主页的标题导航与正文。

整理建议：用语义标签组织页面骨架；链接、标题和按钮各司其职。验收阅读顺序与操作语义。

#### UI-04 Markdown

来源：[对应词条](https://spicytater.cn/terms/markdown)。

案例概括：将周末计划文档呈现为页面。

整理建议：文档源与渲染结果保持对应；保留标题、列表和链接结构，验证目录跳转与强调文字。

#### UI-05 状态 State

来源：[对应词条](https://spicytater.cn/terms/state)。

案例概括：重新进入订单时查看配送结果。

整理建议：明确状态保存位置、更新条件与恢复规则；暂时的视觉切换和持久订单值分别处理。

### 按钮与链接

#### UI-06 按钮 Button

来源：[对应词条](https://spicytater.cn/terms/button)。

案例概括：资料保存与流程确认。

整理建议：按钮执行动作，提供明确名称和反馈；提交过程中防止重复操作，页面跳转使用链接。

来源限制：该页部分演示配置暂不可用；文字说明可参考，实际组件行为需自行实现并验证。

### 表单

#### UI-07 自动完成 Autocomplete

来源：[对应词条](https://spicytater.cn/terms/autocomplete)。

案例概括：输入车站后挑选候选。

整理建议：根据输入给出候选，选中后回填正确对象；说明无匹配与自由输入边界，键盘能移动和确认候选。

#### UI-08 复选框 Checkbox

来源：[对应词条](https://spicytater.cn/terms/checkbox)。

案例概括：为成员组合阅读编辑导出权限。

整理建议：每项可独立选择，多项同时成立；说明选中含义，不将互斥选项误做多选。

#### UI-09 日期选择器 Date Picker

来源：[对应词条](https://spicytater.cn/terms/date-picker)。

案例概括：在营业日范围内预约就诊。

整理建议：说明可选日期区间和禁用日期；非法日期不可提交，选中值回显，区分浏览月份与完成选择。

来源限制：该页部分演示配置暂不可用；文字说明可参考，实际组件行为需自行实现并验证。

#### UI-10 表单 Form

来源：[对应词条](https://spicytater.cn/terms/form)。

案例概括：姓名与邮箱一起保存。

整理建议：字段有持续标签，说明必填和校验；整组提交后显示结果，错误定位到具体字段并保留已有输入。

#### UI-11 输入框 Input

来源：[对应词条](https://spicytater.cn/terms/input)。

案例概括：创建项目的短名称。

整理建议：承接单行自由值，标签与控件绑定；提示文字不替代标签，长说明和固定分类分别采用其他控件。

#### UI-12 数字输入 Input Number

来源：[对应词条](https://spicytater.cn/terms/input-number)。

案例概括：班车订位人数。

整理建议：定义最小值、最大值和步长；直接输入与加减使用同一规则，越界与不可用操作有明确反馈。

#### UI-13 链接 Link

来源：[对应词条](https://spicytater.cn/terms/link)。

案例概括：进入课程资料或帮助页面。

整理建议：入口名称说明去向，使用真实地址；区分站内跳转和新窗口，避免把一次业务操作伪装成链接。

#### UI-14 单选框 Radio

来源：[对应词条](https://spicytater.cn/terms/radio)。

案例概括：报名时选定一种到达方式。

整理建议：同组只允许一个选中值；给出组标题和各项说明，更换选项后旧值被替换。

来源限制：该页部分演示配置暂不可用；文字说明可参考，实际组件行为需自行实现并验证。

#### UI-15 评分 Rate

来源：[对应词条](https://spicytater.cn/terms/rate)。

案例概括：课程结束后评价满意度。

整理建议：定义评分上下限与当前分数，用户能修改选择；提交结果与临时选中状态区分。

#### UI-16 选择器 Select

来源：[对应词条](https://spicytater.cn/terms/select)。

案例概括：选择发布目标环境。

整理建议：只允许定义好的选项，显示当前选择与空值提示；固定集合不能由任意自由文本替代。

#### UI-17 滑块 Slider

来源：[对应词条](https://spicytater.cn/terms/slider)。

案例概括：调整购物预算范围。

整理建议：显示当前数值、单位和范围；滑动与结果变化关系明确，键盘也可调节。

#### UI-18 开关 Switch

来源：[对应词条](https://spicytater.cn/terms/switch)。

案例概括：决定是否接收每周通知。

整理建议：展示开启与关闭的真实含义，说明修改何时保存；状态文字与控件同步，不用开关承接一次性提交。

#### UI-19 文本域 Textarea

来源：[对应词条](https://spicytater.cn/terms/textarea)。

案例概括：输入多段版本发布说明。

整理建议：支持多行自由文本，保留换行；标签持续可见，长度约束依据业务需求定义。

#### UI-20 时间选择器 TimePicker

来源：[对应词条](https://spicytater.cn/terms/time-picker)。

案例概括：在可用时段预订会议室。

整理建议：限定合法小时分钟和时间步长，显示选中结果；与当前日期相关的可用规则明确。

#### UI-21 上传 Upload

来源：[对应词条](https://spicytater.cn/terms/upload)。

案例概括：向相册添加一张照片。

整理建议：区分本地选择、正在传输和上传成功；显示文件名、进度与失败结果，按任务定义文件类型和大小。

### 内容展示

#### UI-22 头像 Avatar

来源：[对应词条](https://spicytater.cn/terms/avatar)。

案例概括：识别评论作者。

整理建议：头像与姓名共同标识身份；缺图时仍保留可识别信息，不影响正文阅读。

#### UI-23 徽章 Badge

来源：[对应词条](https://spicytater.cn/terms/badge)。

案例概括：显示未读数或审核状态。

整理建议：小型标记附着于对应对象，明确数量或状态含义；更新值时入口与标记保持一致。

#### UI-24 卡片 Card

来源：[对应词条](https://spicytater.cn/terms/card)。

案例概括：浏览有时间地点的活动。

整理建议：单张卡片承载一个对象，将标题、说明和详情入口收拢；跨卡字段顺序一致，避免嵌套装饰容器。

#### UI-25 描述列表 Descriptions

来源：[对应词条](https://spicytater.cn/terms/descriptions)。

案例概括：阅读单个订单的收件与配送信息。

整理建议：使用字段与值的成对结构，按用途分组；需要多条记录横向比较时切换为表格。

#### UI-26 列表 List

来源：[对应词条](https://spicytater.cn/terms/list)。

案例概括：按顺序处理待办。

整理建议：每行承载一个可识别项目，保持顺序及对应动作；状态更新后定位与上下文仍明确。

#### UI-27 统计数据 Statistic

来源：[对应词条](https://spicytater.cn/terms/statistic)。

案例概括：查看今天完成量及其变化。

整理建议：说明主数值、单位和比较基准；趋势有对象与时间范围，缺失数据不伪装为真实零值。

#### UI-28 表格 Table

来源：[对应词条](https://spicytater.cn/terms/table)。

案例概括：比较订单编号状态金额与时间。

整理建议：同字段沿列对齐，每行对应一条记录；列头与金额单位明确，窄屏保持比较能力。

#### UI-29 标签页 Tabs

来源：[对应词条](https://spicytater.cn/terms/tabs)。

案例概括：在同一课程中切换概览资料讨论。

整理建议：标签切换对象内的内容区域，当前选中项可辨；切换后仍保留课程上下文。

#### UI-30 标签 Tag

来源：[对应词条](https://spicytater.cn/terms/tag)。

案例概括：标注文章主题和难度。

整理建议：标签表达轻量分类，是否可筛选或移除要明确；不承担整个对象详情和主要业务动作。

### 弹窗与提示

#### UI-31 警告 Alert

案例概括：预约前提醒缺少电话。

#### UI-32 弹出层 Popover

### 页面布局

#### UI-33 盒模型

来源：[对应词条](https://spicytater.cn/terms/box-model)。

案例概括：调整卡片内容与留白。

整理建议：分开内容、内边距、边框与外边距；按实际盒尺寸解释拥挤和溢出，避免盲目压缩文字。

#### UI-34 卡片网格

来源：[对应词条](https://spicytater.cn/terms/card-grid)。

案例概括：比较一组活动卡。

整理建议：卡片内容结构一致，轨道与间距明确；随宽度改变列数，先保证最小可读宽度。

#### UI-35 CSS

来源：[对应词条](https://spicytater.cn/terms/css)。

案例概括：调整注册卡片和按钮外观。

整理建议：在既有语义结构上调整颜色间距边界；视觉变化不改变控件职责，检查修改范围。

#### UI-36 Flex 布局

来源：[对应词条](https://spicytater.cn/terms/flex)。

案例概括：沿一个方向排列订单摘要。

整理建议：用于一维排列，定义方向、对齐、间距和换行；不要为二维对齐反复嵌套。

#### UI-37 页脚 Footer

来源：[对应词条](https://spicytater.cn/terms/footer)。

案例概括：页面底部的帮助版权和返回入口。

整理建议：组织必要的辅助导航与信息，链接去向明确；内容结束后自然可达，窄屏重排。

#### UI-38 Grid 布局

来源：[对应词条](https://spicytater.cn/terms/grid)。

案例概括：按行列排列课程概览。

整理建议：定义二维轨道、间距和跨列关系；宽度变化时仍按同一网格对齐。

#### UI-39 响应式布局

来源：[对应词条](https://spicytater.cn/terms/responsive)。

案例概括：桌面活动列表转为手机排列。

整理建议：按信息优先级调整结构与列数，不缩小整张桌面图；窄屏保留标题、状态与主要操作。

#### UI-40 侧边栏

来源：[对应词条](https://spicytater.cn/terms/sidebar)。

案例概括：长文旁的章节导航。

整理建议：目录对应真实章节，标记当前位置；窄屏换成可打开的目录，正文与导航保持关联。
